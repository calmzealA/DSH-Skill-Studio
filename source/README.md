# Skills Studio · 技能工作台

[English](README.en.md) · [完整安装与发布指南](docs/INSTALL.zh.md) · [0.2.2 变更说明](CHANGELOG.md) · [验证记录](docs/VERIFICATION.md) · [调研依据](docs/RESEARCH.zh.md)

为 **DeepSeek Harness** 制作的 Skills 管理插件，由 **IT咖啡馆 X 老陈聊AI** 共同打造。把技能文件、调用设置、资源、来源更新与恢复放进同一个工作台，并查看技能在所选工作区和模式中能否使用。

**版本：0.2.2。社区插件，与 DeepSeek AI 无官方隶属关系。** 本地交付包可以直接安装；本文中的 `YOUR_GITHUB_USER` 和公开包地址均为发布示例，不能当作已上线下载地址。

## 0.2.2 的使用体验

| 需要做什么 | 在哪里操作 |
| --- | --- |
| 查看当前模式能用什么 | 默认「当前模式」只列出所选工作区、模式实际能调用的技能，不再把技能库总数当作可用数。 |
| 管理全部技能文件 | 切换到「技能库」查看完整清单，再搜索、编辑、导入、导出或操作文件开关。可切换卡片。 |
| 选择工作区和模式 | 顶部使用 DSH 的「工作区」「模式」名称，显示具体工作区和模式名称。选择只改变工作台查看范围，不改变会话设置。 |
| 对照聊天中的 `/` 菜单 | 点击「/ 手动调用」统计查看允许手动调用的技能；模型自动使用的技能单独统计。两者不一定相同。 |
| 修改调用方式 | 在本地技能详情「概览」分别控制模型自动选用和 `/` 手动调用，再保存调用设置。正文和其他元数据保留。 |
| 保存失败后继续 | 短暂文件占用会有限重试；仍失败时，错误留在保存区域，未保存内容保留，可重试或复制错误详情。 |
| 导入技能 | 从 GitHub 或本地文件添加，选择「导入到」，点「下一步」，查看技能后点「导入」。遇到同名技能才显示具体提醒。 |
| 查看保存位置 | 点「保存位置」旁的提示图标查看并复制路径，长路径不再挤占主界面。 |
| 管理完整技能包 | 创建、编辑、导入、导出完整技能包；查看、上传、编辑和移除配套资源。 |
| 更新与恢复 | 对照 GitHub 来源更新；文件哈希防覆盖；变更历史支持恢复。 |

中英文跟随 DSH 设置。说明集中在可点击的「?」中；保存成功只显示简短结果，必要的同步详情可展开查看。

新建或导入成功后自动打开「技能库」，方便找到刚添加的技能；它是否在所选模式中可用仍看「当前模式」。

内容检查属于结构诊断，不代表第三方技能安全认证；导入不会执行其中的脚本。完整资源管理针对可读取的本地技能包；插件或运行时提供的虚拟技能仅供查看合成指令。

## 安装或升级

解压交付 ZIP，找到 **`dsh-skill-studio-0.2.2.tgz`**。安装使用这份 npm 格式包，外层 ZIP 保存源码和文档。

**DSH Desktop：** 打开「插件 → 更多 → 安装第三方插件」，输入新 `.tgz` 的本地绝对路径，安装后启用，并按宿主提示重载。升级时仍安装到原 Desktop 环境。

**DSH Web：** 在新包所在目录执行，升级时使用原 profile：

```sh
dsh --version
dsh plugin --profile web add ./dsh-skill-studio-0.2.2.tgz
dsh web
```

Windows PowerShell：

```powershell
dsh plugin --profile web add ".\dsh-skill-studio-0.2.2.tgz"
```

普通 npm CLI 不管理 Desktop 的保留 profile；桌面用户使用应用内安装器。已经运行的 Web 按安装结果处理重载或重启。

**从旧版升级不迁移技能或历史目录。** 技能保留原位置，工作台历史仍位于 `$DSH_HOME/skill-studio`（默认 `~/.dsh/skill-studio`）。保留旧的 `dsh-skill-studio-0.2.1.tgz` 和原交付 ZIP，需要回退时安装旧包；0.2.2 另存为新交付。更早的 0.1 包也可自行保留。重要技能仍建议先导出完整 ZIP。

## 当前模式与技能库

默认「当前模式」回答“这里现在能用哪些技能”；「技能库」保留扫描到的本地技能，以及当前模式由插件提供的只读项。例如技能库有 40 项，而所选模式实际只提供 8 个可调用技能时，默认列表应显示实际可用的 8 个，不会把其余文件标成该模式已启用。数量随宿主实际结果变化，8 不是极简模式的固定数量。

「当前模式可用」「模型自动使用」「/ 手动调用」统计可点击筛选；自动与手动是两个独立集合。要和聊天输入框的 `/` 菜单核对，先让工作台顶部的工作区、模式与该会话一致，再选择「/ 手动调用」。仅允许模型自动使用的技能不会出现在手动列表中；两种调用都关闭的技能也不计为可用。

目录无法完整确认时，界面明确显示无法确认，不把未知结果写成“0 个可用”。插件自带的只读技能显示提供方信息，不显示会让人误以为可以切换的蓝色开关。

| 查看对象 | 表示什么 |
| --- | --- |
| 技能库中的文件开关 | 只管理文件启用 / 停用；不代表所选模式实际会提供它。整体停用通过重命名指令文件实现，可能影响读取同一文件的其他模式或 Agent。 |
| 所选模式下的可用性 | 宿主实际目录是否提供该技能，以及是否允许模型自动选用和用户 `/` 手动调用。它不表示模型已经读取全文。 |
| 已加载的会话正文 | 聊天历史中曾经读入的内容；文件修改、停用和菜单刷新不会回写这段历史。 |

同名技能可能有多个副本；详情会显示当前实际使用的版本，修改其他副本不会改变它。`~/.agents/skills` 属于共享根，在这里停用可能同时影响其他 Agent；DSH 专用副本可放在 `.dsh/skills`。

旧版可能出现「文件已保存，但 `/` 菜单仍旧」：相关 SDK 的会话技能列表存在缓存，保存文件不会自动清除客户端缓存。0.2 在检查实际目录后刷新菜单桥：**当前打开的技能菜单组会先撤下，重新打开菜单时获取新列表**。界面先显示简短保存结果，目录和菜单的同步详情放在提示图标中；“已保存”不表示所有模式都能使用该技能。

刷新只涉及技能菜单桥，不重启 Agent、不改写聊天历史。其他窗口需已加载插件、连接正常且处于可见状态，才会按约 5 秒周期检查变更；隐藏窗口恢复可见时再检查。若宿主缺少对应公开接口或刷新失败，以同步详情为准，可重新打开菜单、重连或新建会话检查后续可用性。

## 保存失败怎么办

短暂占用会自动重试；若保存仍失败，关闭可能占用文件的编辑器或同步程序，检查目录写入权限，再点击重试。不要为了消除提示而关闭详情，未保存内容仍保留。若提示文件已在其他地方修改，先重新读取并合并内容；重试不会绕过防覆盖检查。
